ouija

AI agents you write in Go — not prompt files.

You write each agent, called a totem, as Go code in your own repo, with types, tests and golden files. A shared engine gives every totem model providers, a sandbox, a cost budget, tracing and editor integration (MCP). A terminal chat shows every tool, every diff and every cent.

~/ouija❯cat WHY.md

Write your workflow as code the model cannot skip

Write "do A, then check B, then merge the results" in a prompt, and the model may skip a step. Write it in Go, and each step is the next line of code: it always runs, and you can test it.

totems · go

Agents are Go types

A totem is an agent written as a Go type. It lives in your repo with unit tests and golden files, and go build turns it into a standalone binary.

sandbox · fail closed

When in doubt, it denies

A filesystem sandbox, an OS sandbox for bash (on by default on Linux and macOS), protected paths, permission levels and a bash allowlist limit what an agent can touch. The engine also stops an agent that repeats the same call in a loop and sanitizes the environment that commands see.

budget · $

Every cent on screen

Each run has a token and cost ceiling, and every reply shows its time, tokens and cost.

trace · json

Traced end to end

ouija records every model call and tool run in a trace you can read later: what was asked, what ran and what it cost.

chat · tui

Shows its work

The chat shows each tool as it runs and each diff side by side, and asks before it writes a file. It also has /undo, @file, search, themes and resume.

mcp · editors

Plugs into your editor

MCP is the protocol editors use to call outside tools. ouija mcp install registers every totem as a tool in Claude Code, Cursor or OpenCode.

The same three steps, written twice. On the left, the model decides whether to follow them. On the right, the steps are the program, so they always run.

AGENT.md · a request 
## Planning
1. Read the relevant files first.
2. Write three independent plans.
3. Verify them, then reconcile.

IMPORTANT: never skip step 3!!
  • the model may still skip a step; "IMPORTANT" is only a hope
  • no code to unit-test or to review
  • cost and tool use are left to chance
plan.go · a program 
// 1. read first
scout, err := eng.Run(ctx, scoutReq(args.Task))
if err != nil {
    return nil, err
}
// 2. three independent passes, in parallel
plans := make([]string, 3)
g, ctx := errgroup.WithContext(ctx)
for i := range plans {
    g.Go(func() error {
        res, err := eng.Run(ctx, passReq(scout.Text, i))
        if err == nil {
            plans[i] = res.Text
        }
        return err
    })
}
if err := g.Wait(); err != nil {
    return nil, err
}
// 3. the next line: it always runs
return reconcile(ctx, eng, plans)

Go decides the steps. The model only judges.

A code reviewer in about 50 lines. Go reads the diff, and the model looks for problems: System tells it how to work, Prompt gives it the data, and Schema fixes the shape of its answer. Then a second call, the skeptic, checks each finding, because the Go loop says so. The totem is a Go type in your own repo, so you need no fork, and it inherits the engine's budget, sandbox, tracing and MCP. Piece by piece →

code 
package review

import (
    "context"
    "encoding/json"
    "os/exec"

    "github.com/discorgento/ouija/engine"
    "github.com/discorgento/ouija/registry"
    "github.com/discorgento/ouija/schema"
)

type Totem struct{}

func (t *Totem) Name() string    { return "review" }
func (t *Totem) Summary() string { return "Review the branch: find problems, verify each one" }

func (t *Totem) Run(ctx context.Context, eng *engine.Engine, args registry.Args) (any, error) {
    // 1. Go gathers the context — what changed since main. Nothing to guess.
    cmd := exec.CommandContext(ctx, "git", "diff", "--no-ext-diff", "--merge-base", "main")
    cmd.Dir = eng.Config().ProjectRoot
    diff, err := cmd.Output()
    if err != nil {
        return nil, err
    }

    // 2. The model judges. System: how to work. Prompt: this call's data.
    //    UseTools: it may open files. Schema: the shape the answer must have.
    found, err := eng.Run(ctx, engine.RunRequest{
        Label:    "find",
        System:   "You review code changes. Report real bugs only, never style.",
        Prompt:   "Focus: " + args.Task + "\n\nDIFF:\n" + string(diff),
        UseTools: true,
        Schema:   schema.Obj(map[string]any{"findings": schema.Arr("one problem each: file, line, why")}, "findings"),
    })
    if err != nil {
        return nil, err
    }
    var out struct{ Findings []string }
    if err := json.Unmarshal([]byte(found.Text), &out); err != nil {
        return nil, err
    }

    // 3. A rule in Go, not a request in a prompt: a skeptic checks every
    //    finding, and only the confirmed ones are kept.
    var confirmed []string
    for _, f := range out.Findings {
        v, err := eng.Run(ctx, engine.RunRequest{
            Label:    "verify",
            System:   "You are a skeptic. Read the code; say yes only if the problem is real.",
            Prompt:   f,
            UseTools: true,
            Schema:   schema.Obj(map[string]any{"real": schema.Enum("is it real", "yes", "no")}, "real"),
        })
        var verdict struct{ Real string }
        if err == nil && json.Unmarshal([]byte(v.Text), &verdict) == nil && verdict.Real == "yes" {
            confirmed = append(confirmed, f)
        }
    }
    return map[string]any{"confirmed": confirmed}, nil
}

func init() { registry.Register(&Totem{}) }
